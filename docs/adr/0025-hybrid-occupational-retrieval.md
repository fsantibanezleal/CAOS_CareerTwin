# ADR 0025: Versioned hybrid occupational retrieval

## Status

Accepted for 0.2.0.

## Decision

ESCO 1.2.1 is the portable multilingual occupational foundation. CareerTwin imports concepts and
graph relations from an operator-downloaded official archive and never sends private profile text to
a taxonomy service. O*NET 30.3 is imported as an English, US-specific enrichment with its release
and provenance retained; it does not replace ESCO identifiers.

Taxonomy search exposes three measured modes: lexical, lexical plus graph degree, and hybrid. Hybrid
adds private `embeddinggemma:300m` vectors generated by the local Ollama service. Every vector stores
its exact model name and installed model digest. PostgreSQL uses a 768-dimension pgvector column and
HNSW cosine index; canonical labels and relations remain relational data.

`benchmarks/taxonomy_retrieval.py` evaluates pinned English/Spanish cases with MRR, recall at 1/5,
p95 latency, and a non-degradation gate against lexical retrieval. A model or weighting change is not
accepted from intuition alone.

## Consequences

- Dataset files are runtime/operator artifacts and are not committed.
- ESCO and O*NET release upgrades require explicit import, benchmark evidence, documentation, and a
  new migration or ADR update where dimensions/contracts change.
- Semantic failure falls back to lexical/graph behavior instead of blocking profile editing.
